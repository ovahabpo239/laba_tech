## 1. Автоматизоване щоденне оновлення

Найпростіший варіант: взяти будь-який хмарний cron-сервіс і запускати скрипт щодня після 10:00 за київським часом (саме тоді НБУ зазвичай публікує курси). На GCP це Cloud Scheduler + Cloud Run Job, на AWS EventBridge + Lambda, на Azure Logic Apps + Function. Якщо інфраструктура вже є на якійсь платформі, краще вписатись туди, ніж тягнути щось нове. З нотифікаціями теж нічого складного: більшість цих сервісів вміють слати email або Slack якщо job впав.

## 2. Перевірка даних з API

Тут декілька рівнів. Перший це базовий retry: якщо запит впав по мережі або прийшов не 200, пробуємо ще раз з паузою. Три спроби з зростаючим інтервалом зазвичай вистачає.

Другий це валідація самої відповіді. Перевіряємо що JSON взагалі розпарсився, що це список і він непустий, що потрібні поля присутні і курс є числом більше нуля.

Третій це бізнес-перевірки. Якщо курс UAH/USD раптом став 5 або 500, це явно щось пішло не так, і краще не писати таке в базу, а кинути алерт.

Щодо відомого кейсу з НБУ: їх API може повернути порожній масив на вихідний або свято, і це не баг з нашого боку. Тут головне не плутати "пусту відповідь" з "помилкою". Retry тут не допоможе, просто скіпаємо дату і не позначаємо як failure.

## 3. ETL процес

Extract: робимо HTTP запит до API НБУ з потрібною датою, отримуємо JSON з курсами всіх валют.

Transform: фільтруємо тільки USD, EUR, GBP, додаємо UAH вручну з курсом 1, перевіряємо які дати вже є в базі і яких не вистачає, приводимо типи до потрібного формату.

Load: пишемо в базу з upsert-логікою. Якщо запис з таким (exchange_date, currency_code) вже є, оновлюємо курс і updated_at, якщо немає, вставляємо новий.
